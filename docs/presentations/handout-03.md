# 3차(최종) 발표 자료 (한글 문서)

> 팀원이 이 글을 읽고 본인 스타일대로 PPT를 제작할 수 있도록 풀어쓴 자료.
> 3차 발표는 약 8분 — **완성된 결과물**, **배포된 라이브**, **향후 발전 방향**, 그리고 **이 프로젝트의 의미**.

---

## 1. 여기까지 왔습니다

캡스톤 디자인의 마지막 발표입니다. 1·2차 발표에서 저희가 무엇을 만들고자 하는지, 어떻게 만들고 있는지를 말씀드렸습니다. 오늘은 **완성된 결과물**을 보여드리는 자리입니다.

CareFit은 이제 단순한 프로토타입이 아닙니다. 실제로 어르신과 장애인분이 접속해서 회원가입을 하고, 카메라 앞에서 운동을 하고, 자신의 기록을 쌓아나갈 수 있는 **완성된 웹 서비스**가 되었습니다.

---

## 2. 완성된 기능 한눈에 보기

지금까지 구현된 모든 기능을 정리하면 다음과 같습니다.

**계정과 인증**
- 일반 회원가입과 로그인
- 카카오 OAuth 한 번 클릭 로그인
- 출생연도 입력 (10년대 단위 큰 버튼)
- JWT 기반 인증
- 비밀번호 BCrypt 해시
- 통합 설정 모달 (이름·연령대·목표 변경, 로그아웃)

**운동 콘텐츠**
- 29개 재활 운동 (의자 12 / 벽·의자 9 / 바닥·매트 8)
- 자세별·부위별·난이도별 분류
- AI 일러스트가 들어간 운동 카드
- 어르신 언어로 작성된 4섹션 가이드
- 카메라 위치 자동 안내 (정면/측면)

**AI 자세 분석**
- MoveNet Lightning 실시간 인식
- 매 프레임 관절 17개 키포인트 추출
- 운동별 세 점 각도 계산
- 두 단계(정상/허용) 판정으로 안전과 동기 부여
- rep 모드 + hold 모드 두 가지 카운트 방식
- 자세 사이클 기반 3단계 state machine

**운동 진행 화면**
- 3-2-1 카운트다운으로 운동 시작
- 영상에 골격선 실시간 렌더링
- 자세 유지 카운트다운 배지
- 단계별 색상 피드백
- 영상 전체화면 모드 (Fullscreen API, 4:3 비율 유지)
- 전체화면에서는 좌상단에 횟수+시간 큰 글씨 오버레이

**결과와 기록**
- 정확도별 축하 메시지와 통계
- 주간 단위 통계 시각화
- 주차별 기록 조회 (52주 전까지)
- 이번 주 목표 진행바
- 연속 운동일 강조
- 주간 추세 막대그래프
- 운동별 상세 카드

**UX**
- 글씨 크기 직접 조절 (PC/모바일 분리 매핑)
- 한국어 어절 단위 줄바꿈
- 색상 기반 피드백
- 모바일 반응형 (네비바 점진적 축소)
- React Router로 새로고침 시 화면 유지

## 3. 시스템 구조 — 어떻게 배포되어 있는가

라이브 서비스가 동작하는 구조를 간단히 설명드리겠습니다.

저희는 **Docker Compose** 기반으로 배포 환경을 구성했습니다. 한 줄의 명령어로 세 개의 컨테이너가 동시에 뜨고, 각자 역할을 분담합니다.

- **nginx 컨테이너** — 사용자가 처음 접속하는 진입점. React로 빌드한 정적 파일을 서빙하고, 동시에 `/api/*` 경로로 들어오는 요청을 백엔드로 프록시합니다. React Router를 위한 SPA fallback 처리도 nginx에서 합니다.
- **Spring Boot 컨테이너** — 백엔드 API 서버. 사용자 인증, 운동 데이터, 기록, 목표 등을 다룹니다.
- **PostgreSQL 컨테이너** — 모든 데이터의 저장소. 영구 볼륨에 데이터가 보존됩니다.

시크릿(DB 비밀번호, JWT 시크릿, 카카오 client secret 등)은 **환경변수로 주입**되어 코드와 분리되어 있습니다. 즉, 같은 코드를 어디에 배포해도 환경변수만 바꾸면 됩니다.

연구실 서버에 SSH로 접속해서 `docker compose up -d --build` 명령 한 줄로 전체 서비스가 떴습니다. 빌드와 배포가 자동화되어 있어, 코드 업데이트가 있을 때마다 git pull 후 같은 명령으로 갱신할 수 있습니다.

## 5. 기술적으로 의미 있는 도전들

이 프로젝트를 진행하면서 기술적으로 어려웠던 부분과, 그것을 해결한 방식을 정리합니다.

### AI 모델을 브라우저에서 직접 실행

처음에는 백엔드에 AI 모델을 두는 것이 자연스러웠습니다. 하지만 그렇게 하면 사용자의 영상이 서버로 전송되어야 합니다. **프라이버시 문제와 서버 비용 문제**가 동시에 발생합니다.

저희는 TensorFlow.js와 MoveNet Lightning 조합으로 AI를 **브라우저에서 직접 실행**하기로 결정했습니다. 그 결과,

- 영상이 사용자의 컴퓨터 밖으로 나가지 않습니다
- 서버는 사용자 데이터와 기록만 다루는 가벼운 REST API가 됩니다
- 사용자가 늘어도 서버 비용이 거의 늘지 않습니다

저사양 노트북에서도 30~50fps가 안정적으로 나오는 것을 확인했습니다.

### 자세 카운트의 노이즈 문제

초기 카운트 로직은 "정자세 0.8초 유지 후 카운트, 1.5초 쿨다운"이었습니다. 단순했지만 문제가 많았습니다. 카메라가 잠깐 흔들리거나, 자세를 풀 때 손목이 무릎에 가려져 키포인트가 사라지면 카운트가 이상하게 올라갔습니다.

이 문제를 해결하기 위해 **3단계 state machine**을 도입했습니다.

- rest → 운동 자세 진입 → holding (시간 카운트)
- holding 시간 충족 → satisfied
- satisfied에서 400ms 이상 자세 풀림 확정 → rest + count + 1

여기에 그레이스 윈도우 300ms를 더해, 한두 프레임의 jitter는 무시되도록 했습니다. 자세를 풀고 일정 시간이 지나야만 비로소 카운트가 올라갑니다.

결과적으로 운동의 본질("잡기 → 유지 → 풀기")에 부합하면서, 노이즈에 강한 카운트가 가능해졌습니다.

### 유지 동작의 별도 처리

플랭크 같은 운동은 횟수가 의미 없고 유지 시간이 본질입니다. 그래서 운동 데이터에 `rep` / `hold` 모드 필드를 추가하고, PoseDetector 컴포넌트가 모드에 따라 다르게 동작하도록 분기 처리했습니다.

hold 모드에서는 자세를 잡고 있는 동안만 시간이 누적되고, 결과 화면에는 "총 유지 시간 N초"가 표시됩니다.

### URL 기반 라우팅과 주차별 기록

초기에는 화면 전환을 React state로 관리했습니다. 하지만 새로고침하면 항상 홈으로 돌아가는 문제, 운동 화면을 URL로 공유할 수 없는 문제, 그리고 주차별 기록을 어떻게 관리할 것인가의 문제가 있었습니다.

React Router를 도입하면서 이 모든 문제가 한꺼번에 해결되었습니다.

- `/exercise/:id` — 운동을 URL로 식별
- `/records?week=-1` — 지난 주 기록을 URL로 표현
- 새로고침해도 같은 화면 복원

## 6. 사용자에게 어떤 의미가 있는가

기술적인 성과도 의미 있지만, 더 중요한 것은 **이 시스템이 실제로 누군가의 삶에 어떤 변화를 만들 수 있는가**입니다.

### 1) 혼자서도 시작할 수 있다

가족이 도와주거나 돌봄 인력이 옆에 있어야만 운동을 할 수 있었던 분들이, 이제는 혼자서도 시작할 수 있습니다. 카카오톡 한 번 누르면 가입이 끝나고, 운동 화면이 직접 무엇을 해야 하는지 안내합니다.

### 2) 잘못된 자세에 즉각 알려준다

영상이나 책으로 운동을 따라 할 때 가장 큰 위험은, **자신이 잘못된 자세로 운동하고 있다는 것을 모른 채** 반복하는 것입니다. 부상으로 이어질 수 있습니다. 저희 시스템은 매 프레임마다 자세를 봐주기 때문에, 잘못된 자세를 그 즉시 알려줍니다.

### 3) 꾸준히 할 동기를 준다

"이번 주 5번 운동, 지난주보다 2번 더 하셨어요!" 같은 메시지, 연속 운동일 카운트, 주간 추세 그래프. 이런 시각적인 피드백은 **꾸준히 할 동기**를 만들어줍니다. 어르신들이 가장 어려워하는 부분이 "지속하기"인데, 저희 시스템은 그 부분을 돕습니다.

### 4) 부담 없는 시작

병원 한 번 가는 데 드는 비용 6만 4천 원, 그리고 이동의 부담. 이런 것들이 없습니다. 인터넷만 있으면 됩니다.

## 7. 향후 발전 방향

이 프로젝트는 캡스톤이 끝나도 가능성이 많습니다.

**연령대별 자동 ROM 조정**
출생연도 데이터가 쌓이면, 70대와 80대에 맞춰 운동 가동 범위를 자동으로 조정할 수 있습니다. 동일한 "앉아서 앞으로 나란히"라도 사용자 연령에 따라 허용 목표 각도가 달라지는 식입니다.

**공공기관 연계**
보건소, 복지관 같은 곳과 연계하면 B2B 모델로 확장할 수 있습니다. 어르신 운동 프로그램에 이 시스템을 도입하면 강사 한 명이 여러 어르신을 동시에 지도하기 어려운 문제를 해결할 수 있습니다.

**PWA 전환**
지금은 웹사이트지만, PWA로 전환하면 모바일 홈 화면에 설치 가능한 앱이 됩니다. 어르신이 매번 주소를 칠 필요가 없어집니다.

**장기 데이터 분석 리포트**
사용자별 운동 진척도를 그래프로 정리해서 **가족 또는 보호자에게 공유**하는 기능을 만들 수 있습니다. 떨어져 사는 부모님의 건강 관리를 자녀가 확인할 수 있는 시스템입니다.

**접근성 강화**
청각 장애인을 위한 자막과 진동 피드백, 시각 장애인을 위한 음성 안내. 사회적 약자의 범위를 더 넓힐 수 있습니다.

## 8. 마무리 — 이 프로젝트가 우리에게 남긴 것

캡스톤 디자인이라는 이름의 학과 과제로 시작했지만, 진행하면서 점점 더 의미 있는 작업이라고 느꼈습니다.

저희가 처음 자료를 조사하면서 본 통계 — **장애인 병원 미방문 이유 1위가 이동 불편 36.5%** — 이 한 줄이 머릿속에서 떠나지 않았습니다. 누군가는 가고 싶어도 못 가고, 누군가는 비용이 부담스러워 포기하고 있습니다. 그분들에게 **별도 장비 없이, 가정에서, 안전하게** 운동할 수 있는 방법을 만들어드리고 싶었습니다.

기술적인 측면에서도 많은 것을 배웠습니다. AI 모델을 브라우저에서 직접 돌리는 방법, 자세 카운트의 본질을 state machine으로 모델링하는 방법, 어르신 친화 UI를 만드는 데 있어서 글씨 크기 하나, 색상 한 가지가 얼마나 중요한지를 직접 경험했습니다.

하지만 무엇보다 의미 있었던 것은, **누군가에게 실제로 도움이 될 수 있는 시스템을 만들었다**는 점입니다.

CareFit은 캡스톤이 끝나도 계속 발전할 가치가 있다고 믿습니다. 시연도 한 번이 아니라, 실제로 어르신들이 사용해보시고 피드백을 주실 수 있는 자리도 만들어보고 싶습니다.

들어주셔서 감사합니다. 질문 받겠습니다.

## 부록 — PPT 제작 팁

- 표지는 깔끔하면서도 임팩트 있게. 슬로건이나 한 줄 카피를 넣는 것도 좋습니다
- "사용자 의미" 슬라이드는 **사진**과 함께 감성적으로 만들면 효과가 큽니다 (어르신이 운동하시는 사진 등)
- 라이브 시연 시간을 PPT에서 충분히 확보하는 게 좋습니다 (3~4분)
- 향후 계획은 **로드맵 형태**로 시각화하면 임팩트가 큽니다
- 마지막 슬라이드는 단순한 "감사합니다"보다는 **프로젝트의 의미를 한 문장으로** 표현하는 것이 인상에 남습니다
